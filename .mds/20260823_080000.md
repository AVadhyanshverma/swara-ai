In this session, we deeply integrated the new `ui_story` cinematic onboarding experience with the main application, overhauled the settings logic, and fixed severe Linux WebKitGTK bugs by migrating the desktop window engine to PyQtWebEngine (Chromium).

## Update: 08:12
- **Permanent Linux PyWebview Flicker Fix**: Diagnosed that the `SharedImageManager` mailbox GL errors were NOT coming from WebGL/Three.js, but from Chromium's internal hardware compositor failing to share DOM rasterization buffers (DMA-BUFs) across the GPU process boundary under XWayland.
- Implemented a robust OS-level fix in `ui/main.py`:
  1. Conditionally forces `QT_QPA_PLATFORM=wayland` if a Wayland session is detected, natively hooking into EGL streams instead of relying on buggy XWayland translations.
  2. Injected Chromium flags `--disable-gpu-memory-buffer-compositor-resources` and `--disable-gpu-memory-buffer-video-frames` to stop Chromium from using zero-copy DMA-BUFs for UI layers, permanently eliminating the "non-existent mailbox" and "texture unit 0" flickering errors across all Linux distributions.

## Update: 08:13

- **Implemented Ultimate Fallback**: Replaced all previous flags with `--disable-gpu-compositing`. This forces the UI layer to composite via CPU (skipping the buggy `SharedImageManager` and DMA-BUFs entirely), while keeping WebGL rendering hardware-accelerated. This guarantees zero flickering and zero crashes on any Linux driver configuration.

## Update: 08:15

It successfully bypasses the broken EGL shared image mailboxes (which caused the flickering) while keeping full hardware-accelerated GPU compositing enabled for maximum 60fps smoothness.

## Update: 08:17
- **Fixed HTML DOM Flickering**: The user reported flickering on the basic HTML `/setup` screen. This was caused by the `--enable-gpu-rasterization` flag, which forces Chromium to use the GPU to paint 2D HTML/CSS elements (Skia GPU rasterization). On many Linux configurations, this is unstable and causes tile flashing.
- Switched flag to `--disable-gpu-rasterization`. This tells the engine to use the CPU to rasterize standard UI elements (which is highly stable and fast enough for DOM), while preserving full GPU Hardware Acceleration for WebGL (`--enable-webgl`) and the Compositor.

## Update: 08:19
- **Input Box Flickering Fix**: Diagnosed a Linux-specific partial swap rendering bug. When clicking an input box (like on `/setup`), the blinking cursor triggers a localized repaint (partial swap). Buggy Linux GPU drivers fail to preserve the rest of the frame buffer during a partial swap, causing the entire screen to flash black/garbage every time the cursor blinks.
- Added `--ui-disable-partial-swap` and `--disable-partial-raster` to `QTWEBENGINE_CHROMIUM_FLAGS`. This forces the compositor to redraw the full window frame instead of just the cursor's bounding box, perfectly eliminating the blinking-cursor flicker while maintaining maximum WebGL hardware acceleration FPS.

## Update: 08:19 (Part 2)
- **Re-applied Memory Buffer Disables**: The logs proved that the partial swap (clicking the input box) actually triggered the `SharedImageManager::ProduceGLTexture` mailbox error. This happens because Chromium tries to create a new DMA-BUF memory buffer specifically for the cursor layer, which fails on the host graphics driver. 
- Re-injected `--disable-gpu-memory-buffer-compositor-resources`, `--disable-gpu-memory-buffer-video-frames`, and added `--disable-dev-shm-usage`. This forces Chromium to use standard CPU RAM (instead of buggy DMA-BUFs or full `/dev/shm` mounts) for passing UI layers to the GPU compositor. This addresses the *root cause* of the mailbox crash without sacrificing WebGL performance.

## Update: 08:26
- **Cross-Platform Dynamic GPU Setup**: Implemented a comprehensive, dynamic `setup_qt_webengine()` function at the top of `ui/main.py`.
- **The Problem**: The user's system is Kali Linux (GNOME) running **Wayland** with an **NVIDIA GeForce GTX 1650**. This specific combination (NVIDIA proprietary drivers + Wayland compositor) fundamentally breaks QtWebEngine's GPU texture sharing, resulting in guaranteed `SharedImageManager` mailbox crashes or `EGL_BAD_CONTEXT` aborts when hardware acceleration is used.
- **The Solution**: 
  - The script now dynamically detects the host OS, Window Manager, and GPU vendor.
  - If it detects `NVIDIA` + `Wayland`, it gracefully falls back to `--disable-gpu` and forces XWayland (`xcb`) to guarantee a stable launch, trading WebGL max FPS for fundamental compatibility.
  - On Windows, it safely uses ANGLE D3D11 for max performance.
  - On all other Linux setups (or if the user switches to an X11 session), it deploys the heavily-tested, flicker-free Linux magic flags (`--use-gl=desktop --ui-disable-partial-swap` etc.) to achieve max FPS without compositor bugs.

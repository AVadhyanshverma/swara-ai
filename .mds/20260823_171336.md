## 2. Streaming Backup Implementation

Replaced the previous `/api/backup` implementation in `ui/main.py`.

The endpoint now:

1. Reads distinct thread IDs from the LangGraph `checkpoints` table.
2. Calls `agent_app.get_state()` for each thread so LangGraph decodes its stored checkpoint state.
3. Converts `HumanMessage`, `AIMessage`, and `ToolMessage` objects into readable JSON records.
4. Streams one thread at a time through `StreamingResponse`.
5. Uses a `first_item` flag for correct comma handling when a thread fails and is skipped.
6. Avoids loading the complete backup into server memory.
7. Returns the file as `swara_chats_backup.json`.

This keeps LangGraph as the source of truth and avoids the disconnected `chat_messages` archival table for explicit backup exports.

## 3. Architecture Decision

The project now treats the system as **local-first and cloud-assisted**:

- Chat history, checkpoints, and workspaces are stored locally.
- Encryption is performed locally through the SQLCipher chat engine.
- Model inference uses hosted endpoints.
- Research and selected document/image workflows may use hosted providers such as Firecrawl, NVIDIA NIM, and Hugging Face.
- The proxy is planned to run on a Hugging Face Space, where its upstream keys will be configured as deployment secrets.

The UI and agent must continue to disclose this distinction accurately.
